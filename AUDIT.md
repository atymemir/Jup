# Аудит текущего Jup

Проверены исходный код, API, миграции, зависимости и основные пользовательские сценарии. Записи и изменения ролей проверяются в отдельной локальной базе с синтетическими аккаунтами. Доступа к production-базе и секретам интеграций в этом окружении нет.

## Исправлено

| Приоритет | Проблема | Изменение |
| --- | --- | --- |
| P0 | Next.js 16.2.6 и две транзитивные production-зависимости отмечены npm как уязвимые | Next.js и eslint-config-next обновлены до 16.4.6, lockfile обновлён. После обновления полный `npm audit` показывает 0 известных уязвимостей. Это результат проверки дерева зависимостей, не утверждение об эксплуатации каждого advisory на конкретном хостинге. |
| P1 | Фото уменьшались до квадрата 384 px; поля внутри файла дополнительно уменьшали полезную площадь | Исходные пропорции сохраняются, поля в файл не добавляются. Верхняя граница — 1536 px; качество и размер подбираются под существующий лимит 160 000 байт. Маленькие оригиналы не увеличиваются. JPEG кодируется асинхронно. |
| P1 | В анкете и модерации нельзя было внимательно посмотреть фото | Добавлен просмотр целого изображения в диалоге, закрытие Escape, состояние ошибки и повторная загрузка. Используется тот же публичный проверенный или приватный авторизованный файл. |
| P1 | Отправка сообщения и запись на урок ожидали внешний Telegram API | Уведомления выполняются через Next.js `after()` после ответа на успешное основное действие. Ошибка доставки не превращает сохранённую запись в ошибку для пользователя. Ошибки отмечаются без содержимого сообщений и реквизитов. |
| P1 | Политика доступа поддерживала только одну жёстко заданную личность владельца | Новая миграция вводит закрытый список владельцев. Подтверждение почты обязательно; текущий владелец сохраняется. Смена адреса или отзыв подтверждения убирают административный доступ. Конкретные новые личные адреса не публикуются в Git. См. `OWNER_ACCESS.md`. |
| P2 | Ошибка получения учебной цели ученика молча скрывалась | Появились понятное состояние загрузки, сообщение об ошибке и повторная попытка. |
| P2 | Неизменившийся список чатов заменял состояние при каждом опросе | Для того же пользователя одинаковый ответ сохраняет предыдущий снимок состояния. |
| P2 | После обновления Next.js изменился интерфейс восстановления страницы ошибки | Обработчик использует поддерживаемый `retry`; проверяется восстановление после намеренно испорченного тестового ответа API. |
| P2 | Длинный заголовок страницы конфиденциальности выходил за экран телефона | Документы корректно переносят длинные слова и адреса. |
| P2 | Фото допустимого размера вместе с подробными сертификатами и многобайтным текстом могло превышать предел всего запроса | Для сохранения анкеты оставлен ограниченный запас до 300 КБ. Предел JPEG в базе остаётся 160 КБ, лимиты сообщений и прочих действий не увеличены. |

Старые файлы, уже уменьшенные до 384 px, нельзя сделать исходными задним числом: для них нужна повторная загрузка оригинала. Новый обработчик не хранит исходный файл размером до 12 МБ; он сохраняет более чёткую версию в пределах текущей схемы базы.

## Проверки

- `npm run build`: производственная сборка Next.js 16.4.6.
- `npm test`: 76 тестов, включая фото, лимиты запросов, отложенные уведомления и подтверждённый доступ совладельца.
- `npm audit`: 0 известных уязвимостей, включая зависимости разработки.
- Lint: ошибок нет; новый линтер отмечает существующие полные переходы через `location.assign`. Их перевод на клиентскую навигацию требует отдельной проверки входа, выхода и смены роли; автоматическое подавление правил не добавлялось.
- Chromium: 12 публичных маршрутов, кабинеты четырёх ролей, сохранение и публикация фото 1024×1536, крупный приватный и публичный просмотр, повторная загрузка цели ученика, восстановление после ошибки страницы. Необработанных ошибок в основных сценариях нет. Отдельно принят профиль размером 246 973 байта с предельным JPEG и подробными квалификациями; ограничения остальных действий проверяются отдельно.

## Следующие шаги по приоритету

1. **Разместить исправления и применить настройку совладельца.** Применить только новую миграцию, внести согласованный адрес в закрытый список и проверить вход в `/findbuddy/admin` с подтверждённой почтой. Локальный тест не означает выдачу прав в рабочей базе.
2. **Надёжная доставка и наблюдение за сбоями.** Добавить долговременную очередь уведомлений с повторными попытками и мониторинг ошибок. `after()` убирает задержку основного действия, но не заменяет очередь, переживающую остановку сервера. Реальную доставку писем и Telegram проверить на двух тестовых аккаунтах.
3. **Уменьшить повторное заполнение.** Сохранять черновики анкет и планов урока с привязкой к аккаунту и версии записи, чтобы возврат к форме не терял текст и не перезаписывал более свежую версию. Быстрые шаблоны и текущие черновики сообщений уже работают.
4. **Подготовить рост каталога.** Перенести поиск и пагинацию на сервер и загружать приватное фото отдельно от больших снимков кабинета. До этого измерить реальные размеры ответа и время RPC на рабочем наборе данных.
