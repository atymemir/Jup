# Доступ совладельцев к модерации

Служебная роль `owner` даёт доступ к `/findbuddy/admin`: проверке анкет, обращениям и истории решений. Действующий владелец сохраняется. Новые адреса настраиваются в закрытой таблице `fb_owner_access`, а не в публичном исходном коде.

## Применение

1. В SQL Editor рабочей базы применить только новую миграцию `supabase/sql/20261125000000_findbuddy_owner_access.sql`. Она не меняет Supabase Auth, не создаёт пользователей и не подтверждает почту. Старые миграции повторять не нужно.
2. Администратору базы добавить согласованный адрес, в нижнем регистре:

   ```sql
   insert into public.fb_owner_access(email)
   values ('co-owner@example.test')
   on conflict(email) do update set email = excluded.email;
   ```

   Адрес в примере — тестовый. Реальные адреса не следует добавлять в публичный Git.

3. Если пользователь уже зарегистрирован и почта подтверждена, роль обновляется сразу. Иначе он регистрируется обычным способом и подтверждает почту. После этого может открыть `/findbuddy/admin`.

Пользователь не получает права через `account_type` в metadata. Изменение почты на адрес вне списка или отзыв её подтверждения автоматически убирает служебную роль. Удаление строки из списка отзывает доступ, сохраняя аккаунт и остальные данные.

## Проверка

`tests/findbuddy-owner-access.test.mjs` проверяет: сохранение первого владельца, активацию уже подтверждённого аккаунта, ожидание подтверждения, регистрацию после настройки доступа, модерацию анкеты совладельцем, отзыв прав после смены/удаления адреса и запрет чтения или изменения списка через обычный пользовательский API.

В облачном окружении нет реквизитов рабочей базы. Локальные тесты подтверждают поведение кода, но не означают, что настройка уже применена в production.
